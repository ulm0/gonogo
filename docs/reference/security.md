# Security

- gonogo listens on `127.0.0.1` unless you pass `--host`. There is no TLS: to reach it from another machine, put a reverse proxy or a private network in front ([recipe below](#reverse-proxy), and [Exposing gonogo safely](../https.md) for what to forward, what never to, Caddy, nginx and Tailscale).
- Every `/api` call and the `/ws` WebSocket need the browser token. The built client files do not; they hold no state.
- **`POST /uplink/<id>` is the route meant for senders outside, and takes no browser token.** It needs the secret of that uplink instead (a signature of the body, or the secret as a bearer token), takes at most 256 KiB and 30 a minute per uplink, and answers 404 alike for an unknown and a disabled uplink. The Host check applies to it as to the rest, and a request with an `Origin` header is refused. **Uplink secrets are stored in plain text** in `uplinks.json` (mode 0600), which an agent in `bypassPermissions` mode can read. What a delivery says is read by an agent as a message from you. **Relay's bot tokens and the signing secrets of Slack and Linear are stored in plain text** in `relay.json` and `uplinks.json` (mode 0600). A token is never logged and never sent back to the browser, but an agent in `bypassPermissions` mode can read the files.
- **Dock only with people you trust: their agents can reach yours.** A docked station can write to every agent of yours as `name@station`, and an agent reads such a message as a request that it may act on, with the permissions you gave it (an agent in `bypassPermissions` mode runs as you). It can also make tasks on your board, assigned to your agents, and see the names, roles and states of your agents. The agents are told to share only what a task needs, which a prompt cannot enforce. `/dock/*` takes no browser token: a call proves itself with a signature made with the secret of that dock (a wrong one, a timestamp more than 5 minutes off and a repeated nonce are refused with 401, at most 60 calls a minute from one dock). Nothing is encrypted by gonogo: use HTTPS or a private network, or the messages and the roster cross as plain text. **The secret is stored in plain text** in `docking.json` (mode 0600), which an agent in `bypassPermissions` mode can read. A docking code works once, for 15 minutes; give it only to the person you mean, and undock at once if a station you do not know appears. The code holds an address, and your server posts to it when you pair, so pair only with a code you got from the person.
- A request whose `Host` is not a loopback name, the bind address or one of your `--allow-host` names is refused with 403, and so is a browser request whose `Origin` is not its own `Host`. This stops other web pages from reaching the port through DNS rebinding or cross-site requests.
- **Payload values are stored in plain text.** The env values and header values of a payload MCP server (a token, an API key) are written to `agents.json` and to the agent's `mcp.json` (both mode 0600), and the page receives them so that Edit can show them. Anyone who can read your home directory can read them, and so can an agent in `bypassPermissions` mode. To keep a secret out of the files, write `${NAME}` in the value: Claude Code expands it from the agent's environment, which is gonogo's own minus the variables gonogo scrubs (its documentation; not tried with a payload server). A payload server is code or a remote service you chose: its tools run with the agent's permission mode.
- Agents never see the browser token. Each start of an agent gets its own token, in the environment variable `GONOGO_TOKEN` and never on a command line, and it opens only the hook and tool endpoints.
- An agent in `bypassPermissions` mode runs as your user. It can read the token files under the home directory, and everything else you can read. The agent tokens stop mistakes and misuse of the API, not a hostile agent.
- Credentials in the environment of gonogo (in the container: `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`) are passed on to the agents (an API key as `GONOGO_API_KEY` in seed mode), so their shells can read them.
- Agents always talk to the server on `127.0.0.1`, whatever address you bind, because Claude Code blocks hooks to private addresses. A Clean Room agent is the exception: its container reaches the server by `host.docker.internal`, which the server accepts as `Host` for the hook and tool endpoints only (the agent token is still needed there, and an `Origin` is still refused). Every other route answers 403 `forbidden host` for that name.
- **A Docker socket mounted into gonogo's container is root on the host** (`compose.yaml` does it, for Clean Room). Every agent in that container can use it, a Clean Room or not; see [Clean Room in the container](../guide/docker.md#clean-room-in-the-container).
- **A Clean Room limits what an agent can reach, not what it can spend.** The container sees the worktree, the agent's own folder (its settings, its token, its notes) and the network; it does not see your home directory, your other projects or your `~/.claude`. It holds your Claude credential (an environment variable of the container), so it can use it, and in `bypassPermissions` it can use the network freely. If you bind `--host 0.0.0.0` so that containers can connect, anyone who can reach the port can try the browser and agent endpoints: the browser token and the agent tokens are then the only gate (the Host check still refuses other names on the browser routes). Real Docker was not used to test any of this.
- **Seed mode trusts the folders you hire agents into.** It records Claude Code's folder trust for each of them, so a repository's own `.claude/settings.json` hooks and permission rules run with your credential before any model turn. Add only repositories you trust. Claude Code's documentation says that trust of a folder also covers its subfolders that are not git repositories themselves, so gonogo refuses to record trust for `/` and for any folder that is or holds your home directory, gonogo's home or Claude Code's configuration folder (that start fails with `cannot record folder trust for <folder>: ...`; the boss is no exception). The entries stay after an agent is removed: gonogo never deletes them. They are the `hasTrustDialogAccepted` keys under `projects` in `<CLAUDE_CONFIG_DIR>/.claude.json` (`~/.claude.json` when the variable is not set, `/state/claude/.claude.json` in the image); delete an entry there to take the trust back.
- The Docker image installs gonogo's dependencies from the repository's `pnpm-lock.yaml`, so it gets the versions and checksums the tests ran on, not the newest release of each. The package tarball carries no lock file (pnpm does not read one from a package): `pnpm dlx` and `pnpm add -g` get the exact versions of gonogo's own dependencies, which `package.json` pins, and resolve theirs at install time.

## Reverse proxy

[Exposing gonogo safely](../https.md) has the longer guide: Caddy and nginx with TLS, which paths must be public (`/uplink/*` and `/dock/*` only), the token, and Tailscale. Serve gonogo at the root of a host name (`https://gonogo.example.com/`), not under a path: the client calls `/api` and `/ws` by absolute path. Start gonogo with `--allow-host gonogo.example.com`, and for nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:7777;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

- By default nginx rewrites `Host` to the upstream address, which makes every request fail the `Origin` check; `Host $http_host` keeps the name the browser used.
- Stopping or restarting an agent can take up to 8 seconds and terminal sockets stay open for hours, hence the long `proxy_read_timeout`.
- Caddy's `reverse_proxy 127.0.0.1:7777` keeps the `Host` header and needs nothing else.
- Uplink webhooks (`POST /uplink/<id>`) go through the same proxy with no change, and need no browser token. To take them from the internet without exposing the page, see [Uplink](../features/uplink.md): a name of its own that forwards `/uplink/` only.
- The browser token travels in the `Sec-WebSocket-Protocol` header of `/ws`, not in the URL, so a default access log does not hold it. Do not log that header.
