## Verified in this room

Evidence is this room's own records (the Black Box, the Mission Log, the task board, the message log, the state folder and `gh`), read after the fact. The Black Box starts at 13:29 UTC on 2026-11-18, so "used" below means about one working day, not weeks. A browser view of these was not looked at unless it says so.

- **Linux, amd64 and the Docker image.** The room runs in a Docker container on x86_64 with Claude Code 2.1.325 (that it is the published gonogo image was not checked).
- **Real `claude` with gonogo's tools.** The Flight Plan (56 tasks; 158 create and update events), the Mission Log (more than 19 entries), mail between agents and to the Director (more than 2,600 messages, 212 of them with `in_reply_to`, so Party Line has real threads: the data, not the view), the Downlink, and `start_agent` (FLIGHT started four consoles, 19:07 to 19:09 UTC). Hop counts are recorded on every message.
- **Costs and quota.** Propellant counted real replies (2,140 ledger lines) and the plan quota came from a real Claude Code status line (`quota.json`).
- **T-minus and Static fire with a real `claude`.** CONTROL's run (Mission Log "real-claude verification 2026-11": no-go to hold, the Director's hold, abort, a Static fire that went and one that broke) and the Director's polls in the Black Box: no-go holds (RETRO, EECOM), a Static fire, a Director hold, and two all-go.
- **Max Q** was set on the wall (4, 3, 2, no limit) with agents working. **Startup policy**, **the room layout reset** and **a livery choice** were used from the page.
- **Clean Room with a real `claude`.** RSO and SIMSUP are Clean Room consoles on real Docker. RSO wrote security reviews to the Mission Log and SIMSUP answered the Director's Static fire from there. Whether their containers were recreated across the server's four restarts that day was not recorded.
- **`auto` permission mode.** All 15 consoles ran in `auto` for the whole day.
- **Saved-state upgrade.** One home went 0.1.2, 0.2.0, 0.3.0; every format is still version 1, so no migration ran.
- **Release.** The release workflow ran for v0.1.1, v0.1.2, v0.2.0 and v0.3.0 (all succeeded; GitHub Releases exist). It is set to publish to npm with provenance; the npm page was not checked.
- **Docker self-update (0.4.0).** EECOM ran it in an isolated docker-in-docker (docker:27.5.1-dind, API 1.47) on a real daemon, twice (Mission Log "self-update manual run 0.4.0" and its e2 re-run on the #79 fix): good update, a second update and UNDO, three failing images rolled back, leftovers removed, a private image refused, and a helper killed during the health wait now leaves an `interrupted` result with no UNDO. Not run: a daemon older than API 1.44 (a unit test only), a helper killed while the old container stops (documented: gonogo stays down until `docker compose up -d`), a registry with credentials, linux/arm64 as a host.

Used by nobody in this room, so still **not run**: Hold on a console and ALL STOP, a hire request through Relief (every hire was the Director's), Relay (no target is set), a docked station (a code was made, nothing was paired), the Plot Board, a model designing a livery, Payload, Launch Window and Uplink with a real model.

## Known limits

- Launch Window: a fire time a DST change skips does not fire that day (in America/Santiago `0 0 * * *` misses the September change). A scheduled message to FLIGHT replaces the wall's MISSION.
- Uplink: an unknown id answers 404 before the HMAC runs, so timing reveals whether an id exists. A record `load()` skips (e.g. a newer kind after a downgrade) is dropped with its secret at the next save, with a warning.
- Flight Plan: the whole list goes in every frame, so a full board nears the 4 MB socket buffer. A task keeps its assignee's name and does not follow a rename. The top-bar count is an `aria-label` on a span, which screen readers other than Chrome's may not read.
- Downlink: every frame carries the whole inbox (about 700 KB at the limits). After a restart, unread mail is found only among the newest 1000 log records.
- Mission Log: with two writers the last write wins, without a warning. Hand edits are seen only after a restart. Ids above `l999999` are not handled. Entries are text a model may follow: not for secrets or untrusted agents.
- Plot Board: one boss writes; a hand edit is seen only after a restart and the next write replaces it. Two browsers are not told of each other's typing; the second to save is told the board moved on.
- Black Box: 600 events a minute at most (the rest are dropped and counted). An agent that exits by itself, the boss created at the first start and refused requests are not events. The files can be edited by anyone who can write your home, an agent in `bypassPermissions` included; git shows it.
- Relay: Telegram updates are not deduplicated by `update_id`. A Slack event is marked handled even when the hub then refuses it, so Slack's retry is ignored.
- Livery: an `oklch` colour outside sRGB is clipped per channel in the check. If removing a custom livery fails on disk after `livery.json` moved back, no livery frame goes out until the next state.
- Relief: requests are kept in memory, so a restart drops them and FLIGHT is not told. A boss saved before Relief keeps its old role text, which says it cannot hire.
- Docking: codes and seen nonces live in memory, so a call replayed within 5 minutes across a restart is accepted once. If the other station accepts a hand-off and the local task then fails to move, the remote copy stays. A queued message to a station is marked undelivered at a restart.
- Engines without the gonogo tools (pi, Qwen, Grok, Crush, Cursor Agent) still get `GONOGO_TOKEN`. gonogo needs `claude` on `PATH` because FLIGHT is always Claude Code.
- Codex, opencode and Copilot take no payload.
- The npm tarball has no lock file; transitive dependencies resolve at install time.
