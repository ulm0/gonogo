# Spec: Rooms as the only mode (draft, 0.5.0, breaking)

Design by FIDO, 2026-11-18, task t58. Status: draft, not built. Read from `origin/main` (0.4.0 plus #82): `cli.ts` (`parseArgs`, `runRooms`, the `--exit-with-stdin` child, the `supervised` refusal of Docker self-update), `supervisor.ts`, `roomproxy.ts`, `roomspage.ts`, `rooms.ts`, `reload.ts`, `home.ts` (token file), `tui-cli.ts`, `Dockerfile`, `compose.yaml`, `packaging/homebrew/gonogo.rb`, `docs/features/rooms.md`. Nothing was run.

## Intent

"Nada de 2 modos." `gonogo` always starts the supervisor. Room `main` is the home itself, as today. A user with one room sees the same address, the same token and the same page; there is just one more process in front.

## Decisions

1. **Main answers at `/`, not only at `/r/main/` (pick).** Option 1 was: `/` is the list and jumps to `/r/main/` when there is one room. It breaks things that hold an address: **Telegram webhooks registered as `https://host/uplink/<id>`** (phone approvals stop silently), the pairing codes and links of docked stations (`/dock/...`), scripts and the TUI that call `/api`. Option 2 (pick): the front port treats any path that is not reserved as a path of `main`. Reserved: `/r/<id>/...` (other rooms, and `/r/main/` too, same room), `/rooms` (the list page), `/api/rooms` (its data), `/internal/` (below), and the supervisor's own `/assets/*.css|woff*` (same bytes as main's). Everything else (`/`, `/api`, `/ws`, `/uplink/`, `/dock/`, the page assets) goes to main through the proxy that exists, with the same rules as the table in `docs/features/rooms.md` (page and `/uplink/`, `/dock/` open, `/api` and `/ws` need the token, `/hook` and `/mcp` 404). `roomOrigin()` already derives from the page's address, so main's webhooks keep their old URL and other rooms show `/r/<id>/uplink/..`. In the page, **Rooms** (Patch Panel) goes to `/rooms`.
   Cost: `roomproxy.ts` gets a default room (about 30 lines and its tests: a path that is not reserved maps to `main`; `/r/main/x` and `/x` reach the same room). Not chosen: Host-name routing, same reasons as before.
2. **One Director token = today's `<home>/token`.** The supervisor reads or makes `<home>/token` (0600, 64 hex). For an existing home this is **the value the user already has**, so every old `http://host:7777/#token=...` link and every stored token in a browser works. `rooms-token` is deleted at start if it exists (one line in the notes). The room child must not use the same secret ("the Director token never reaches a room"): a room's own browser token moves to `<room home>/run/room-token` (0600). In code: `openHome(dir, { tokenFile })`, default `token`, and the child mode passes `run/room-token`. Non-main rooms then have no `token` file at all. The supervisor learns each room's token from the child's `gonogo ready:` line as now.
3. **CLI.** `gonogo [--home --port --host --allow-host --pty-host --no-update-check]` is the supervisor (what `gonogo rooms` is today). Flags mean the **front port**: `--port` and `--host` bind the supervisor, `--allow-host` is the Host list of the front, `--home` is the root. Children always get `--host 127.0.0.1 --port <their own>` and inherit `--pty-host` and `--no-update-check` (as arguments, `roomArgs` exists). `gonogo rooms add|list|remove` stays. `gonogo rooms` with no action is kept as an **alias of `gonogo`** for one release, then removed. The child entry is hidden: **`gonogo __room [flags]`** (today's plain run), not in `--help`, refuses to start without `--exit-with-stdin` and with a terminal on stdin ("internal: run `gonogo`"). `startGonogo()` stays the library function the tests call, so most of the 3000+ tests do not change; the CLI `parseArgs` tests do. The supervisor prints one line `gonogo ready: http://127.0.0.1:7777/#token=...` (the word `rooms` leaves the line, so scripts that parse it keep working; the child's line stays as it is, on the pipe). Scripts that read the line and call `/api/...` at that address keep working through the proxy.
4. **A second supervisor on one home is refused**: `<home>/run/supervisor.lock` (same helper and stale-lock rule as `gonogo.lock`, new file name). A leftover **plain gonogo from 0.4.0** still holds `gonogo.lock`: main's row shows the existing "another gonogo is using the home" note.
5. **The child's port stays the same across a child restart (needed for live reload).** Agents keep the hook and MCP URL they were started with, and their pty host survives a reload; a `--port 0` child gets a new port and the surviving agents then talk to nothing. Fix: the child writes its port to `<home>/run/port` and asks for that port first; busy means a new one (the agents' hooks then break, and the room's page says "agents must be restarted", the existing stale-hook path if there is one; otherwise log it). This is already true of today's `gonogo rooms`; it was not noticed because rooms are new.
6. **`gonogo reload` and live reload.** Today a room re-executes itself (`relaunch`), which under a supervisor would fight the restart logic. New: `gonogo reload` signals the **supervisor** (`run/supervisor.lock` pid, SIGUSR2). The supervisor sends SIGUSR2 to each child; a supervised child hands over (hub down, pty host kept) and **exits 75** instead of relaunching; the supervisor then closes its port and **re-executes itself** (`relaunch`, `GONOGO_RELOADED=1`, same argv), and the new supervisor starts every child with `GONOGO_RELOADED=1` (they wait for the lock and adopt their pty hosts). The front port is down for a few seconds; pages reconnect. A crash (not 75) keeps the backoff; 75 never counts as a failure. Without `--pty-host` the agents stop, as `gonogo reload` says today. `gonogo reload --home <dir>` targets another root. Per-room reload is **not** built.
7. **The TUI.** `gonogo tui` connects to the front port with the Director token (`<home>/token`, today's default, so nothing changes for main); new `--room <id>` (default `main`) adds the prefix `/r/<id>`. `gonogo tui --home <room dir>` for a non-main room stops working (it has no `token`); the help says `--room`.
8. **Docker.** Image `CMD` stays `["--host","0.0.0.0","--port","7777"]` and now means the supervisor. **Healthcheck probes `/rooms`** (the supervisor's own page, 200 whenever the supervisor is up), not `/` (which would be 503 while main restarts and flap the container). `compose.yaml`: `stop_grace_period: 60s` (every room stops in parallel, 12 s each, plus the 17 s wait before SIGKILL); the comment "another instance" becomes "add a room: `gonogo rooms add`". Clean Room containers keep `container:self` and their room's own `host.docker.internal:<child port>`.
9. **Docker self-update (#75) works under the supervisor; recreating the container restarts every room.** Rules: the **Update key works only in room `main`** (its home is the root, where `update.json` is read after the swap; other rooms show "update from the main room"). Before the swap, `main`'s `busy()` must also be false for every other room: the child asks the supervisor, `GET http://127.0.0.1:<front>/internal/busy` with its own room token as bearer (the supervisor knows each token), answered only for a loopback `Host` and a loopback peer, 404 otherwise and never proxied. The supervisor answers from a field `busy: string | null` it reads in each room's `/api/state` (the poll text; the builder adds the field to `/api/state` if it is not there). Free-text refusal says which room. The `supervised` refusal in `cli.ts` goes. The swap itself needs no change: it stops the container (SIGTERM, supervisor, children) and starts the new image.
   npm and pnpm installs: the page's Update runs the install, then `triggerReload`; for a supervised child `triggerReload` signals its parent supervisor with SIGUSR2 (env `GONOGO_SUPERVISOR_PID`), i.e. item 6. Again only from `main`.
10. **Other features, checked, no design change.** Autostart (`docs/autostart-spec.md`): per room child, the host starting `gonogo` at boot is the same command. Phone approvals and Uplink webhooks: main keeps `/uplink/<id>` and `/dock/`, others `/r/<id>/...`; one Telegram bot per room (said in `docs/features/rooms.md`). Docking: unchanged. Hooks and MCP: per room loopback, unchanged. Rollout's install kind (`npm`, `pnpm`, `docker`, `brew`, `unknown`) comes from `argv[1]`, the same file for supervisor and children, so unchanged; `gonogo update` still prints one command. **Homebrew formula: no change** (it installs the same bin and tests `--version`); after `brew upgrade` the user runs `gonogo reload`, as for npm.
11. **Login (`docs/login-spec.md`) gets simpler, and has to be built on this.** The login lives **only in the supervisor**: one `auth.json`, one setup, one set of sessions with `Path=/` (one cookie covers `/` and `/r/<id>/`), one rate limiter, one tamper alarm, one step-up list, one Host normalizer (the front port; the children see only loopback Hosts). What was R8 ("rooms") becomes the baseline: every child's browser door is its `run/api.sock` (0600), the supervisor reaches it, and **no child accepts a token on TCP**; there is no plain mode with a token of its own to protect. The local `token` file is the credential of the unix socket door of the supervisor (`<home>/run/api.sock`, used by the TUI). Order: **PR 1 and PR 2 of this spec come before login PR 1**; `docs/login-spec.md` gets a one-paragraph note, RSO re-reads it.

## What breaks for an existing user (0.5.0 notes, in `CHANGELOG`/release text)

- `gonogo` is now two or more processes: a supervisor and one per room (tens of MB each). `ps` shows `gonogo __room`.
- `--port`, `--host`, `--allow-host` apply to the front; the room itself listens on a loopback port of its own.
- Anything that talked to the room's real port, or read `<home>/token` as the room's token, now talks to the front and the Director token. Same address, same token value, so links and scripts keep working; **bookmarks with `rooms-token` do not** (the rooms feature is two releases old).
- A plain gonogo of 0.4.0 left running on the same home holds its lock: stop it first.
- A non-main room cannot be reached with `gonogo tui --home`: use `--room`.
- Docker: `stop_grace_period` 60 s in `compose.yaml` (people who copied the compose file keep 15 s: rooms may be killed mid-shutdown; said in the notes); healthcheck path changes with the image.

## Scope: two PRs, release together (a build between them refuses Docker update for everyone)

**PR 1, single mode core (about 450 lines with tests):** CLI switch and `__room`, Director token = `token` and the room token file option, `rooms-token` cleanup, the default room in the proxy, `/rooms` and the Patch Panel link, `supervisor.lock`, the stable child port, reload through the supervisor (exit 75, SIGUSR2, re-exec), TUI `--room`, Dockerfile healthcheck, compose, docs (`rooms.md`, README start line, `--help`, `docs/https.md` webhook paths if they name `/uplink`), release note text.
**PR 2, update under the supervisor (about 250 lines with tests):** `/internal/busy`, the `busy` field, main-only Update, `triggerReload` to the supervisor, removing the `supervised` refusal, docs of Rollout and Self-update.
**Left out:** per-room reload, a stop/start key per room, Host-name routing, a separate update per room, a machine-wide Max Q.

## Tests

CLI parse: no subcommand is the supervisor; `rooms` alias; `__room` refuses a terminal and a missing `--exit-with-stdin`; flags go to the front, `--pty-host` reaches children. Token: an existing home's `token` is unchanged and works as the Director token; a room child's token differs from it and is in `run/room-token`; the Director token is never in a child's environment, arguments or ready line; `rooms-token` is removed. Proxy: `/`, `/api/state`, `/ws`, `/uplink/x`, `/dock/x` reach main with the room's token swapped in; `/r/main/api/state` and `/api/state` give the same answer; `/hook`, `/mcp` are 404 at both; `/rooms`, `/api/rooms`, `/internal/busy` never reach main; a room id `rooms` or `internal` is refused by `validRoomId` (builder checks the pattern: `rooms` is a valid id today and must be reserved, so are `api`, `assets`). Supervisor: a second supervisor is refused; a child that exits 75 restarts at once with `GONOGO_RELOADED=1` and no backoff; SIGUSR2 on the supervisor ends all children, re-executes with the same arguments (a fake command, as `test/fake-room.mjs`); a restarted child asks for its old port. Docker: healthcheck path answers 200 while main is down; update refused when another room has a poll open (message names it), allowed from `main` only; `/internal/busy` is 404 for a non-loopback Host and for an unknown token. Not testable here: a real container swap with several rooms, brew, a browser.

## Risks

- Two addresses for main (`/` and `/r/main/`): a page opened at `/r/main/` and one at `/` share the token and storage (same origin), but notification tags and the "open in a second tab" habit may differ. Harmless, said in the docs.
- Reserved root names are a contract: a future route at `/rooms` or `/internal` in a room collides. The proxy test lists them.
- A supervisor that is down means every room is down (one more thing that can fail); the children end with the pipe, and `restart: always` or the service manager restarts the supervisor. The pty host keeps agents alive meanwhile when `--pty-host` is on.
- Reload re-executes the supervisor: a bug in the new supervisor means no front port. Mitigation: none beyond the supervisor test that re-executes with the same arguments; the old process cannot keep the port while the new one binds it, so a failed start is a failed reload, and `gonogo` by hand starts it again (agents stay in their pty hosts).
- I did not check whether `/api/state` already carries the poll text, nor how stale hook URLs are handled today (item 5); the builder reads both before coding.
