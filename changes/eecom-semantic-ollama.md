- **Search by meaning: gonogo can run its own Ollama.** The block has two modes. **Managed** (the default for a new setup, Linux x64 and arm64) needs nothing installed: the Docker image carries the pinned Ollama (the CPU part of 0.40.18, 79 MB), and anywhere else gonogo downloads that release once (1.6 GB, checked against a pinned sha256 before it is opened, 79 MB kept), starts `ollama serve` itself when an entry has to be indexed (on `127.0.0.1` and a port of its own, in its own process group, with an environment of its own), pulls the model with progress, restarts it with a backoff if it dies, stops it when it is idle, over a memory limit, when the feature is turned off and when gonogo stops, and shows its state, memory, settings and log. **Remote** keeps every rule of the endpoint and the confirmation, and takes an API key for an Ollama behind a proxy (sent as `Authorization: Bearer`, over https or to this machine only; kept in its own 0600 file and never shown). Embedding on a CPU takes about half a second a piece: an index of 2,000 pieces takes about 20 minutes in the background.
