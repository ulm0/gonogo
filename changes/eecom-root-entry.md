- **Docker: a bind folder Docker made root's is fixed by the container.** The image starts as root for one job: `gonogo-entrypoint` gives uid 1000 the **top** of gonogo's own bind targets that are root's (`$HOME`, the data folder above `$GONOGO_HOME`, `$CLAUDE_CONFIG_DIR` and the working directory), only a real directory that is a mount point (or directly in one), never recursively, never through a symlink, never `/` or a system folder, and says so in the log. Then it drops to uid 1000 with the container's own groups (the Docker socket's `group_add`, not root's) with `setpriv`; the server, the rooms and the agents run as uid 1000 as before. `--user 1000` skips it and keeps the warning. So `install -d -o 1000 -g 1000` is no longer needed (ZimaOS, Portainer). **What breaks:** `docker exec` starts as root now: the `gonogo` command drops to uid 1000 by itself, other programs do not (`docker exec -u node gonogo gh auth login`; a file written as root in `/home/node` is root's until the next start, which hands the root-owned regular files and folders inside the home to uid 1000, never across a mount, never through a symlink, and never a file with a second link, so a hardlink planted to a root file is left alone); PID 1 (`tini`) is root; the image's `USER node` is gone (a self-update from an older image makes the copy start as root, and its helper runs as uid 1000). [Docker](https://gonogo.ulm0.com/guide/docker.html).
