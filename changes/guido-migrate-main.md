- **An older install's room main moves into `rooms/main/` by itself.** At the next start, before any room, gonogo moves main's files (not the supervisor's) from the root of the home into `rooms/main/`, so every home looks the same. It is a rename in one filesystem with a journal: a crash is finished at the next start, `main.home` in `rooms.json` is written last. The move is refused, and nothing changes, while a room is running, when an agent works in a folder inside the home (a worktree or a Clean Room), or when a check fails; the reason shows on main's card with MIGRATE NOW, DRY RUN and DISMISS, and it is not tried again by itself. After a move the card has UNDO. `gonogo rooms migrate-main [--dry-run | --undo]` does it from the command line (stop gonogo first). **Before going back to a build older than 0.8.2, run `gonogo rooms migrate-main --undo`** (or UNDO on the page and restart once; the update strip's UNDO in Docker refuses until then): an older build looks for main at the root and would start an empty one there; your main is still in `rooms/main/` and going forward again finds it.
