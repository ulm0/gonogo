- **Fix: the Docker self-update finds its own container when the hostname is not its id.** On an install whose container has a compose `hostname:` (or another name the daemon gave), the Update key was off with "No such container: <hostname>". gonogo now takes its container id from its own files (the mounts of `/etc/hostname`, `/etc/hosts` and `/etc/resolv.conf` in `/proc/self/mountinfo`, the cgroup in `/proc/self/cgroup`: Docker, rootless Docker, Podman, Kubernetes forms), then from the hostname, then from the one running container with its network address, and never chooses between two. When it cannot tell, the Update strip and the AUTO-UPDATE block say why instead of only "run the command on the host".
